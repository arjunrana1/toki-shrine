## Current rules

- Apps/sites owned by another ON or OFF block remain unavailable with “Already added to a block”, no owner name/dialog/transfer. Wait for ownership maps before enabling selection. Failed stale-draft save retains the editor/draft and inline conflict message. Storage protection: [persistence/events](persistence-events.md).
- Create/edit cannot leave contents step or save without targets, including direct friction edit; temporary empty selection is allowed while editing. Never introduce a legacy migration for the prior one-time empty-test-block cleanup.
- Name input is single-line, capped at 30; displays may wrap without ellipsis. No legacy-long-name migration required by owner.
- Website Add requires a complete domain: ASCII dot-separated labels, no edge hyphens, letters-only TLD of at least two characters; whole domain only, no IDN/punycode. Canonical surrounding whitespace/trailing dot/case handling remains. Preserve interior pasted newlines so invalid multiline input is rejected, never merged; Enter inserts nothing.
- **Unlock minutes (11 October §17 addendum, [closed task](../../coordination/tasks/TS-unlock-minutes/TASK.md), code `1060024`):** a block has no pause length; the user picks 5/10/15/20 minutes (`AppConfig.UNLOCK_MINUTE_CHOICES`) at the gate for each pause session. No screen shows a typing-time estimate: Review (5/5) and Block detail show the character count only, and turn-on has no estimate sub-line (`Estimate.kt` is deleted; `formatCountdown` lives in `Countdown.kt`). Exact copy lives in PRD §17; do not copy stale mock values.
- Target lists: shared vertical icon/label/divider rows, four-row internal scroll bound and overflow indicator. Contents selection scrolls with bottom Next pinned. Save/summary must remain reachable.
- Detail has one activation switch; edit/delete unavailable while ON. **Add more** (P7-F5, 8 October addendum; UI: `AddMoreScreen.kt`) is the exception: `BlockRepository.addTargets(id, apps, sites)` saves additions while ON. Pass the full selection (existing + new); omitting an existing target throws `TargetRemovalException` and changes nothing, another block's target throws `ConflictingOwnershipException` (show "Already added to a block"). Additions reach detection on the blocks flow's next emission; during an active pause of that block they share the pause until re-arm (pause is per block). Delete OFF asks Confirm/Go back. While ON, the APPS & SITES row shows Add more instead of Edit; it opens the standalone "What should this cover" screen (no step indicators, no Next): existing targets render locked, the full selection saves through addTargets ("Confirm and Save Block"), Never mind/Back return to detail with nothing saved. Redesigned friction Edit opens 3/5 and Back returns to detail; content Edit opens 1/5.
- Create Back closes search first, then unwinds steps, then records abandonment once on exit. Edits exit silently; successful edit logs fields_changed from before the write. Terminal guards prevent duplicate save/abandon actions and release on rejected save.
- Home bottom actions are Feedback (no icon) and wider New Block. Feedback is implemented in Phase 7 and awaits owner acceptance. Turning OFF uses the implemented Phase 5 typing/waiting gate inherited from the block's method, with separate disable difficulty; no direct OFF bypass.
- New-block review keeps Save pinned and now shows the later owner-approved helper `Turn it on from the "Blocks" homescreen.` beneath it; the block still saves OFF and activation remains a separate gated action. This 19 September owner correction supersedes only the older no-helper presentation, not save behavior.
- App search shows `loading...` directly below the search field until installed apps finish loading, then replaces it with the applicable result state/count. Keep target rows inert until ownership data is available. The owner accepted the loading and review-helper presentation on `f92661d`.

## Implemented wizard redesign

See PRD §7 and §17's 19/23 September amendments and the [closed implementation task](../../coordination/tasks/TS-block-wizard-redesign/TASK.md). Five screens: contents, name, method, disable difficulty, review. Step 3 is inline cards (09 v3, UM-B, 11 October): "How do you want to pause the block?", **Type a passage** and **Wait it out**, each unfolding its single stepper when selected (one open at a time, each keeps its own draft value), with the hint "You'll pick how long each pause lasts when you unlock." A new block starts with neither card selected and Next is dimmed and disabled until one is picked (`CreateFlowState.methodChosen` / `methodStepComplete`); an edit opens with the stored method chosen. There is no details sheet, "Adjust the details" button or Reset. Pause values are the same in every build and live in `AppConfig` (§17 23 October pre-launch config values addendum, [TS-config-values](../../coordination/tasks/TS-config-values/TASK.md)): typing 30..150/10, default 40; pause wait 30..120/10 seconds, default 30; no per-block pause length. Release disable values: 150/200/300 characters or 1/2/4 minutes, with the middle rung preselected ("Wait for 1 minute." is singular). The disable ladders live in `src/{release,debug}/…/data/repo/ChallengeValues.kt`; debug lowers only the first rung to 20 characters / 20 s, preselected, for owner testing. Edit prefill clamps stored pause values into range and moves a stored disable value that is off the ladder to the nearest rung (a tie goes to the harder rung), so an older block always re-saves; unedited blocks keep their stored values. Typing passages draw from 330 words (`AppConfig.TYPING_WORDS`).

These values are pinned by `DebugChallengeValuesTest`, and release values by `ProductionChallengeValuesTest`. Stored values are preserved and enforced as stored; new and re-saved writes enforce the current bounds, and edit prefill clamps both methods' stored pause values into range and onto the step grid. `CreateFlowStateSaver` is position-indexed (17 slots: `showDetails` removed and `methodChosen` added in UM-B; `flowId` stays last), and a saver of the older shape fails its casts and starts fresh. Preserve edit cancellation, direct entry, draft restoration and save guards. Challenge typo highlighting is submission-gated and has no preference. Challenge execution and pause lifecycle are implemented and closed in Phases 5–6; Phase 7's production-value device checks remain pending.
