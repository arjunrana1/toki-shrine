## Current invariants

- App/site identity belongs to exactly one block through global unique constraints. Create/update reject cross-block ownership atomically; no move/transfer path. A stale draft cannot steal a target from an ON or OFF owner. In-draft duplicates collapse. Rejected writes preserve all prior data.
- New blocks save OFF. Both create/update require at least one target and the current values: pause countdown 30..120 seconds in increments of 10, typing 30..150 in increments of 10 (the same in every build, `AppConfig`; §17 23 October pre-launch config values addendum), and the variant's fixed disable ladders. Blocks have no pause length (schema v6). Prior ranges, including 1..1200, are superseded. Existing stored test values are not rewritten merely by opening the database.
- Domain canonicalization at storage boundary trims, removes one trailing dot and lowercases; package identity is case-sensitive. UI full-domain validation is a separate layer; see [blocks/targets](blocks-targets.md).
- State transition plus block_turned_on/off event commit in `setEnabledRecordingTransition`; unchanged stored value emits no transition. Internal bare setEnabled is not a replacement public activation path. UI activation gating belongs to [navigation/permissions](navigation-permissions.md).
- `completeOnboarding` transaction pairs completion event and one-way app_meta marker at most once. Preserve first_launch_at independently through insert-if-absent semantics.
- Events survive block deletion: no cascading event FK. Child target rows cascade with their block. Historical retired conflict events remain; do not emit new conflict shown/resolved events for the removed UI.
- The active event taxonomy has three uses: product-critical outcomes, feature engagement and diagnostics. `bubble_dragged` and `challenge_abandoned` are retired alongside the existing conflict/stall events: preserve historical rows, but do not emit them or include them in the Phase 7 active-event audit. Bubble dragging remains product behavior; `countdown_started`/`countdown_completed` remain active.
- `walk_away.source` values are `EventTaxonomy.WALK_AWAY_SOURCES`: `block_screen`, `typing`, `countdown` and `auto_away` (8 October §17 addendum, P7-F3); `recordWalkAwayAndCount` rejects any other source. `auto_away` is not a new event name: after 15 s continuously away (`ChallengeRuntime.AUTO_NOPE_AWAY_MS`, elapsed realtime, away-start kept in instance state across recreation) a pause gate/challenge takes the same walk-away transaction as a chosen nope — raw event, inclusive daily count, Stats nope with the usual valuation and unchanged dedup, idempotent per session — and shows no Walk-Away moment. A turn-off challenge away for 15 s records `turnoff_abandoned` exactly like Never Mind. Shorter absences stay nonterminal (typed text cleared and the wait restarted on return); configuration changes are never away; a commit in progress wins.
- `BlockRepository.addTargets` (P7-F5 "Add more") is the one target write allowed on an ON block: add-only, the full selection must still contain every existing target (`TargetRemovalException` otherwise), cross-block ownership rejects (`ConflictingOwnershipException`), all in one transaction; nothing else on the block changes and no event is written. Detection picks up additions from the blocks flow.
- Event target_type distinguishes app/site; do not infer it from dotted strings. New Stats records site outcomes against the hosting browser package (4 October §17 addendum; the raw event keeps the domain target); the raw in-the-moment global walk-away count retains both.
- Redesigned Stats uses the transactionally paired outcome ledger, frozen baseline and local usage cache under [stats.md](stats.md), not the legacy raw-event denominator. Outcomes store their local date and immutable saved contribution; counted nopes + app pause successes form resolved attempts. Preserve injectable clocks/test fixtures.
- The pause length is the gate's per-session choice (TS-unlock-minutes UM-4): `ChallengeRuntime.enterChallenge(now, minutes)` accepts only `AppConfig.UNLOCK_MINUTE_CHOICES`, at GATE, for a pause; the value lives in the runtime snapshot (`BlockActivity` instance state `challenge_unlock_minutes`) and in `CompletionRequest.unlockMinutes`. `ChallengeRepository.completePause` writes nothing for a request without a valid choice. `pause_started.minutes` carries it (`PauseCoordinator`); `block_created` and `block_edited.fields_changed` no longer carry `pause_minutes`.
- Pause completion records `challenge_completed`; turn-off completion records `turnoff_completed` with its OFF transition, without inflating the walk-away denominator. Challenge marker/event writes live in `ChallengeRepository` transactions; bare `EventRepository.log()` is not the only event-writing path.
- Analytics remain local Room events under PRD §10. [PostHog](../plans/posthog-analytics.md) is proposed follow-up work; local persistence/Stats must remain independent of any future upload result. The local event table includes target identity and is not an approved remote payload.

## Open obligations and limits

- Schema v4 adds Stats tables with explicit MIGRATION_3_4 and preserves v3 blocks/targets/events/meta. Schema v5 (P7-F6) adds only `stats_visit_override` with explicit MIGRATION_4_5; existing baselines are not recomputed. **Schema v6 (11 October §17 unlock-minutes addendum)** drops `blocks.pause_minutes`. The owner accepted a data reset for this upgrade only: `TokiDatabase.build` uses `fallbackToDestructiveMigrationFrom(3, 4, 5)`, and because Room rejects migrations that start or end at those versions, MIGRATION_3_4/4_5 are no longer registered (kept with schemas 3–5 as history; `StatsMigrationTest` still checks that chain against 5.json). There is no global destructive fallback: a same-version reopen keeps every row, and any version after 6 needs an explicit migration registered in `TokiDatabase.build`. Export every version. No pre-v3 installs are supported. Android upgrade tests are compiled, not executed: the v3/v4/v5→v6 reset, the same-version reopen and Android recreation of the chosen minutes (UM-RN1) belong to the launch-gate Android test run. The owner's real v5→v6 upgrade opened without a crash (UM-O7, 22 October 2026). Do not confuse the earlier v3 no-op upgrade evidence with v3→v4 proof.
- Typo positions have no user preference and appear only after an explicit failed Submit. The `show_typos` column is gone as of schema v3; nothing writes or reads it.
- Phase 3 transactional pairings have executed Room evidence in [OWNER-CHECKS](../../coordination/tasks/TS-P3-validation/OWNER-CHECKS.md): transition/event and onboarding marker/event commit together, forced event failures roll back the paired mutation, and repetitions remain at most once.
- Edit/delete OFF gating is part of UI behavior; do not overstate it as universally enforced by every repository API. Inspect the relevant path if changing this boundary.
- Previous GLM PASS WITH NOTES applies only to 89ef9e3. Stats redesign data implementation and forthcoming GLM UI require a new scoped review; owner/device and migration execution remain pending in [the task](../../coordination/tasks/TS-P7-stats-feedback-final/TASK.md).
