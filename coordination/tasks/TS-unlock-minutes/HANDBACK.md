### What changed
- **UM-1 schema v6.** `Block.pauseMinutes` is gone; `TokiDatabase` is version 6 and `6.json` is exported (the `blocks` table has no `pause_minutes`; identity `f369b35f…`). New `TokiDatabase.build(context, name)` is the single shipped configuration: `fallbackToDestructiveMigrationFrom(3, 4, 5)` and no registered migrations, because Room 2.6.1 rejects a migration that starts or ends at a destructive start version. `TokiApplication` uses it. `MIGRATION_3_4`/`MIGRATION_4_5` and schemas 3–5 stay as history. There is no global `fallbackToDestructiveMigration()`. The tests use `build()` too, so they check the shipped configuration rather than a copy of it.
- **UM-2 config.** `AppConfig` holds the pause values for every build: typing 20–150/10, default 20; wait 20–240 s/10, default 60; `UNLOCK_MINUTE_CHOICES = listOf(5, 10, 15, 20)`. `PAUSE_MINUTES_*` are removed. - **UM-3 repository.** `BlockDraft.pauseMinutes` and its validation are removed; create and update enforce the new pause bounds. Reads don't validate, so stored out-of-range values keep working as stored (completion compares the stored amount) until re-saved.
- **UM-4 runtime.** `ChallengeConfig` no longer has a pause length. `ChallengeRuntime.enterChallenge(nowMs, minutes)` accepts a value only at GATE, only for a pause, and only from `UNLOCK_MINUTE_CHOICES`; otherwise it returns null and stays at the gate. The activity-result extra became `EXTRA_UNLOCK_MINUTES = "unlock_minutes"`; nothing reads it (recording seam only).
  - **Implementation decision for the reviewer:** a restored *pause* snapshot that is ACTIVE or COMMITTING without a valid length (in practice, instance state saved by the previous build) goes back to GATE to pick again. The challenge still has to be passed, so this is never a way in. A completion already written for that session is idempotent (`completionExists`). The alternative of finishing with a default length would invent a length the user never chose.

### Decisions for the reviewer
- **The row reserves its space instead of overlaying.** The handoff's `position:absolute` is met by giving the row a constant height under the challenge button, always composed (alpha 0 when closed), so opening never moves the buttons. An overlay outside its parent's bounds would not receive touches in Compose, and a fixed-height box would clip at large font scales. Closed, the row is hidden from touch (`enabled = false`) and from accessibility (`clearAndSetSemantics {}`), which also lets the fold-away play.
- **Meme lift by padding.** At about 412 × 891 dp (the S23 Ultra class) all fifteen `sys_block_*` images are width-limited with at least 343 dp of vertical slack (`sys_block_14` is the tightest; computed from the JPEG sizes), so the 152 dp padding is a pure 76 dp rise. A taller image scales down instead of being cut off at the top, which keeps the PRD's "fully visible".
- **Chip hold.** 200 ms (150 ms colour change plus a beat). PRD says "brief"; this is the one tunable.
- **Direct-entry edit.** Opening the friction editor straight at step 3 composes with nothing chosen for a frame, then the stored card unfolds with the animation once prefill lands. Entering through the wizard, or coming back from step 4, shows it open at once.
- **Typing and wait values are shown in the steppers as before** (`N characters`, `formatCountdown`); no estimate anywhere on step 3.
